# 预检整批容量，运行中按需分配缓存块

首版静态单 batch 在开始计算前，根据各请求 prompt 长度和最大生成长度，保守检查整批所需的历史块与状态槽位是否能同时容纳；容量不足时在计算前报错。检查不等于将全部未来块编号分配给请求。

运行中按即将参与计算的 token 位置准备缓存容量，只在现有块不足时申请新增编号。采样产生但尚未参与计算的 token 不视为已有有效 KV。窗口与压缩过程状态在请求开始时统一申请状态槽位，结束时与历史块一起归还。

该方案保留按需扩容接口，同时利用当前固定请求集合与明确长度上限，避免为首版引入运行中抢占和重算。代价是保守准入：即使请求可能提前结束，最大容量检查仍可能拒绝它。此保证以没有其他并发请求争用同一缓存池为前提。
